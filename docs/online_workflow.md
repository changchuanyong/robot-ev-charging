# 在线位姿流程收敛（2026-11-05）

> 本文档合并了原「在线位姿流程收敛」「现有图片的孔位与位姿改进」「九孔孔口平面与深度确认」三篇，原文件已删除，历史版本见 Git 提交。

正式目标是连续、可靠地输出机械臂所需的充电口位姿。历史图片用于复现缺陷和回归验证，复核建议不作为控制输入。D415、D435 共用采集、曝光和孔位提取实现，通过明确的设备配置选择。

## 保留的正式流程

`CaptureColorCamera / RGBControls → PosePipeline._extract_points → pnp2 → 带时效与质量状态的位姿 → 原子发布 → 控制侧验收`

- 采集预览使用同一段孔位提取代码，保留候选、孔名、误差及同帧图像用于排查；不再试多种预处理回退。
- `RealSenseCamera` 复用采集相机，补充控制输入所需的时钟映射和独立标定校验。两种型号均检查实际设备与配置的型号、序列号和分辨率是否一致。
- 曝光直接在预览窗口用 A、[ / ]、- / = 调节；同一 `RGBControls` 负责范围、步进、回读与退出恢复。正式定位使用配置中的同一 `rgb_options`，不另开曝光扫描脚本。
- 预览的帧过期、同帧绑定、断帧时界面响应继续保留。正式发布保留错误帧、时钟、质量及停止失效保护。

预览和持续发布可以使用同一份 `config/realsense_config.json`。先设置 `device_model` 为 `D415` 或 `D435`，填写真实序列号、对应流配置和独立验证的标定。预览与发布先后启动，不能同时占用同一设备：

```powershell
conda activate ev-charging
python -m ev_charging.vision.launch ev_charging.capture.preview --config config/realsense_config.json --no-library
python -m ev_charging.vision.launch ev_charging.vision.locate.run --config config/realsense_config.json
```

输出仍为 `dataset/live/latest_control_pose.json`，保留帧号、主机单调时间、相机坐标系、米制变换、相机与标定身份、质量和有效状态。当前配置的序列号及标定尚未填写，本次没有将其伪造成已验收状态。

- 3 张现存冻结图的完整特征及位姿与原基线一致。删除尺度放宽补丁后，原 `anchor_gate` 冻结字段不一致也随之消除。

- 合成九孔动态输入通过真实 `run.main`、`PosePipeline`、PnP 和临时原子 JSON 输出：两个变化位姿逐帧发布；过期、坏图、正常停止、异常断开和用户中断都输出无效状态并清空旧位姿。输入明确标为 simulation。
- 两种型号的设备验证、曝光应用/恢复、时间映射、重复帧及标定拒绝用模拟 SDK 验证，没有连接真实机械臂或相机。

单次回放的预热后耗时中位数约 172 ms、P95 281 ms，首帧约 2.53 秒；这是本机保存帧处理时间，不能当作采集 FPS 或实机动态精度，也不能跨运行据此宣称速度提升。没有放宽质量和时效门槛来提高通过率。

当前控制器只在视觉阶段接收目标，进入预对准后冻结位姿。连续发布链的软件验证不代表运动中的视觉跟踪已实现。真正上线仍需要相机身份、内参/手眼标定、与实际孔口一致的几何参考，以及现场连续图像验证。本轮保留了已有孔口几何修改，没有擅自切换坐标原点或标定状态。

以后新增代码必须对应正式流程中可复现的缺陷，并用同一正式路径证明有效位姿覆盖率、错误孔名/误接受、重投影误差、延迟或稳定性确实改善。没有收益就回退；不能把更多候选点、更多开关或更长回退链当成改进。

本轮证据位于 `artifacts/workflow_cleanup_20261105/`：`before_cleanup.zip` 保存清理前源码、配置、测试和文档；`excluded_rgb.zip` 保存删除图片及记录；`removed_images.json`、`counts.json`、`replay.json`、`tests.txt` 记录删除范围、规模、回放和测试结果。未提交或推送 Git。

## 现有图片的孔位与位姿改进

日期：2026-11-04。此次仅改进离线复核建议和图片评价，不启动相机或机器人，不重训模型，也不修改原始标注、训练参数或控制门槛。

### 使用方法

重启九孔复核服务后，新的候选补全自动生效：

```powershell
conda activate ev-charging
python -m ev_charging.review.review_keypoints
```

对已有图库图片比较三维模型：

```powershell
python -m ev_charging.vision.evaluation.evaluate_library_keypoints --annotations dataset/vision/keypoint_annotations.json --output-dir artifacts/keypoint_pose_comparison --geometry config/geometry_nominal.json --geometry config/geometry_cad_socket_openings.json
```

每次使用新的输出目录。只有保存了与图片绑定、哈希一致且分辨率匹配的相机参数时才计算位姿；不会用其他设备或近似内参补齐。所有位姿结果均不授权机器人运动。

### 孔位结果与证据边界

使用冻结的同一份标注、同一权重和 5 原像素诊断邻域。13 张已确认图片共有 81 个可见参考点，其中 58 个为人工编辑，23 个为原样自动建议；后者不是独立精度证据。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 同名候选落在参考点 5 px 内 | 29/81 | 33/81 |
| 人工编辑参考点中匹配 | 6/58 | 10/58 |
| 原有匹配丢失 | — | 0 |
| 可见参考点上的输出偏差超过 5 px | 0 | 0 |
| 非可见/不确定参考孔名上仍有输出 | 1 | 1 |
| 完全无输出的图片 | 8/13 | 8/13 |
| 两张具备完整九孔参考的图中，完整输出九孔 | 0/2 | 1/2 |

所有原有预测坐标保持不变，新增四个匹配均来自人工编辑参考点。一张图由 6 个候选补全为 9 个。上述是同批开发回归，图片已经用于诊断和方案比较，不是独立测试集。

实现只在已有主孔、PE、方向与结构证据一致时补全缺失的小孔；补点必须来自已测量的内孔边界，保持尺寸约束、拓扑和唯一性。辅助暗区轮廓需在多个强度水平稳定出现，输出取真实拟合轮廓的中心，不取模板投影或平均坐标。已有候选不会被替换。

直接把更多阈值候选加入全局匹配的试验虽然恢复了更多点，但也新增了多处超过 5 px 的中心偏差，未采用该方案。控制/实时定位前端及原匹配门槛保持原样。
